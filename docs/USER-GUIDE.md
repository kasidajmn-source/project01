# คู่มือการเข้าใช้งานและการป้องกันสิทธิ์ (เวอร์ชัน 1.0.5)

> อ่านฉบับย่อได้ในเว็บ เมนู **คู่มือ** (`#/help`)

## 1. ใครเป็นอะไร

| ผู้ใช้ | ได้มาอย่างไร | ทำอะไรได้ |
|---|---|---|
| **ผู้ดูแลระบบ** | Google: บัญชีที่ติดตั้ง Apps Script (เสมอ) + รายชื่อในหน้าตั้งค่า · SharePoint: ผู้ที่กด "สร้างรายการข้อมูลในไซต์" + รายชื่อ · OneDrive: เจ้าของ OneDrive ที่เก็บโฟลเดอร์ (เสมอ) + รายชื่อ | ตั้งค่าที่เก็บข้อมูล กำหนดผู้บริหาร/ผู้ที่สร้างโครงการได้/เกณฑ์สี ดูและแก้ข้อมูลได้ทุกโครงการ ลบหรือโอนเจ้าของโครงการ — **ไม่พิจารณาอนุมัติแทน และไม่แต่งตั้งสมาชิกในโครงการที่มีเจ้าของ** |
| **ผู้บริหาร** | ผู้ดูแลระบบใส่อีเมลไว้ | ดูทุกโครงการ อ่านอย่างเดียว |
| **สมาชิกแผนก** | ผู้ดูแลระบบใส่อีเมลรายคน (ตั้งค่า → ผู้ใช้และสิทธิ์ของระบบ) | ดูทุกโครงการและความเคลื่อนไหว อ่านห้องสนทนาของโครงการอื่น (อ่านอย่างเดียว) คุยในห้องแผนก นัดประชุมแผนก |
| **เจ้าของโครงการ** | ผู้สร้างโครงการ (ต้องอยู่ใน "ผู้ที่สร้างโครงการได้") | ทุกอย่างในโครงการ และเป็น**ผู้เดียว**ที่แต่งตั้ง/ถอดถอนสมาชิก กำหนดสิทธิ์ ลำดับกรรมการ และขั้นตอนพิจารณา |
| สมาชิก | เจ้าของโครงการแต่งตั้งด้วยอีเมล | ตามบทบาท: ผู้ควบคุมงาน · คณะกรรมการ (มีลำดับ 1, 2, 3 … และประธาน) · ผู้รับจ้าง · หัวหน้า/ผู้บริหาร · ผู้ติดตาม |
| คนอื่น | — | **ไม่เห็นโครงการ** (Google: ขอรหัสเข้าระบบไม่ได้ ถ้ากำหนด "ผู้ที่สร้างโครงการได้" ไว้) |

**ลำดับเริ่มงาน:** ผู้ดูแลระบบตั้งค่าที่เก็บข้อมูล → ผู้สร้างโครงการสร้างโครงการ (= เจ้าของ) → เจ้าของแต่งตั้งสมาชิกในแท็บ **สมาชิกและสิทธิ์** (ระบบส่งอีเมลแจ้ง) → ส่ง **ลิงก์เชิญทีม** → สมาชิกเข้าระบบด้วยอีเมลที่ถูกแต่งตั้ง

## 2. วิธีเข้าใช้งาน

### Google Drive (Apps Script) — แนะนำเมื่อมีผู้รับจ้างภายนอก

**ผู้ดูแลระบบ (ครั้งแรก)**
1. สร้าง Google Sheet ในบัญชีที่จะเป็นเจ้าของข้อมูล → ส่วนขยาย → Apps Script → วางโค้ด `backend/Code.gs`
2. เลือกฟังก์ชัน `setup` → เรียกใช้ → อนุญาตสิทธิ์ (ดู Access key ในบันทึกการทำงาน)
3. ทำให้ใช้งานได้ → เว็บแอป: ดำเนินการในฐานะ **ฉัน**, ผู้ที่มีสิทธิ์เข้าถึง **ทุกคน** (การตรวจสิทธิ์อยู่ในโค้ด)
4. เปิดเว็บ → ตั้งค่า → Google Drive → ใส่ URL `/exec` + Access key → **บันทึกและเชื่อมต่อ**
5. หน้าต่างเข้าสู่ระบบ: ใส่**อีเมลบัญชีที่ติดตั้ง** → รับรหัส 6 หลักทางอีเมล → ใส่รหัส
6. ตั้งค่า → ผู้ใช้และสิทธิ์ของระบบ: ใส่ "ผู้ที่สร้างโครงการได้" เช่น `@egat.co.th` (**สำคัญ**: ถ้าเว้นว่าง ใครที่มีลิงก์เชิญก็ขอรหัสเข้าระบบได้)
7. กด **ลิงก์เชิญทีม** ส่งให้ทีม (ลิงก์มี Access key — ส่งเฉพาะคนในทีม)

**ผู้ใช้ทั่วไป**
1. เปิดลิงก์เชิญทีม → กด **เชื่อมต่อ**
2. ใส่อีเมลที่เจ้าของโครงการแต่งตั้งไว้ → **ส่งรหัส** → นำรหัส 6 หลักจากอีเมลมาใส่ (ใช้ได้ 10 นาที ผิดได้ 5 ครั้ง ขอได้ 5 ครั้ง/ชั่วโมง)
3. อยู่ในระบบได้ 30 วันต่อเครื่อง · ออกจากระบบได้ที่ ตั้งค่า → บัญชีของฉัน

### SharePoint (Microsoft 365)

**ผู้ดูแลระบบ:** ขอฝ่าย IT ลงทะเบียนแอป (SPA) + Grant admin consent `Sites.ReadWrite.All`, `Sites.Manage.All` (+`Mail.Send`) → ตั้งค่า → SharePoint → ใส่ Tenant / Client ID / URL ไซต์ → **ลงชื่อเข้าใช้และตรวจสอบ** → **สร้างรายการข้อมูลในไซต์** (คุณจะเป็นผู้ดูแลระบบ) → **บันทึกและเชื่อมต่อ** → เพิ่มทีมเป็นสมาชิกไซต์ → ส่งลิงก์เชิญ

**ผู้ใช้ทั่วไป:** เปิดลิงก์เชิญ → **เชื่อมต่อ** → ลงชื่อเข้าใช้บัญชีองค์กรในหน้าต่าง Microsoft (อีเมลต้องตรงกับที่ถูกแต่งตั้ง) · ลงชื่อเข้าใช้ใหม่ทุก 24 ชั่วโมงตามนโยบาย Microsoft

### OneDrive

**ผู้ดูแลระบบ**
1. ลงทะเบียนแอป (SPA) สิทธิ์ `Files.ReadWrite`, `Files.ReadWrite.All` (+`Mail.Send`) — องค์กรส่วนใหญ่ต้องให้ IT กด **Grant admin consent** สำหรับ `.All`
2. ตั้งค่า → OneDrive → Client ID + ชื่อโฟลเดอร์ → **ลงชื่อเข้าใช้และตรวจสอบ** → **สร้างโฟลเดอร์ข้อมูล** → **บันทึกและเชื่อมต่อ**
3. หลังแต่งตั้งสมาชิก กด **ให้สิทธิ์เข้าถึงโฟลเดอร์** (แก้ไขได้ = ผู้ที่ต้องบันทึก / ดูอย่างเดียว = หัวหน้า ผู้ติดตาม ผู้บริหาร) แล้วส่ง **ลิงก์เชิญทีม**
4. ถอดสมาชิกแล้ว ให้ถอนสิทธิ์ใน OneDrive → โฟลเดอร์หลัก → จัดการการเข้าถึง ด้วย

**ผู้ใช้ทั่วไป:** เปิดลิงก์เชิญ → **เชื่อมต่อ** → ลงชื่อเข้าใช้บัญชี Microsoft ที่ได้รับแชร์ (ถ้าขึ้นว่าไม่มีสิทธิ์ ให้ผู้ดูแลกด "ให้สิทธิ์เข้าถึงโฟลเดอร์" ก่อน)

### โหมดทดลอง
ข้อมูลอยู่ในเบราว์เซอร์เครื่องเดียว **ไม่มีการป้องกันสิทธิ์จริง** (ปุ่ม "ทดลองใช้งานในนามผู้อื่น" ใช้ดูมุมมองของแต่ละบทบาท) — ใช้ฝึก แล้วย้ายข้อมูลขึ้นที่เก็บจริง

## 3. ลำดับการอนุมัติและการโหวต

1. **ผู้ควบคุมงาน** — คนใดคนหนึ่งพิจารณาได้
2. **กรรมการลำดับที่ 1 → 2 → 3 …** — ทีละคนตามลำดับ (คนถัดไปได้รับอีเมลเมื่อคนก่อนผ่าน)
3. **ประธานกรรมการ** — คนสุดท้าย

- เจ้าของโครงการกำหนดลำดับในตารางสมาชิก (ช่องลำดับใต้บทบาท "คณะกรรมการตรวจรับ") ลำดับซ้ำไม่ได้
- ขั้นคณะกรรมการของแต่ละหมวดเลือก "ทุกคนเรียงตามลำดับ" (ค่าเริ่มต้น จำนวนวัน = วันต่อคน) หรือ "คนใดคนหนึ่ง"
- ไม่ผ่านขั้นใด → ตีกลับผู้ส่ง (ต้องระบุเหตุผล) → ผู้ส่งแก้ไขส่งใหม่ → เริ่มขั้นแรก
- **โหวตเลือกรูปแบบ/สี** (แบบไม่ได้กำหนด): ผู้ส่งติ๊ก "ให้คณะกรรมการโหวต" ตอนส่งเรื่อง หรือผู้ควบคุมงานกด "เปิดให้คณะกรรมการโหวต" — ตัวเลือก 2–8 แบบ แนบรูปได้
  กรรมการโหวตคนละ 1 เสียง (เปลี่ยนได้จนปิด) · ครบทุกคน: เสียงข้างมากชนะ / เท่ากันใช้เสียงประธาน · ประธานหรือเจ้าของปิดโหวตก่อนครบได้ (คะแนนเท่ากันต้องเลือกชี้ขาด)
  ขั้นคณะกรรมการ/ขั้นสุดท้ายกด "ผ่าน" ได้หลังได้ข้อยุติ (กด "ไม่ผ่าน" ได้ตลอด)

## 4. ห้องสนทนาและการประชุม (1.0.4)

| ห้อง | อ่านได้ | พิมพ์ได้ |
|---|---|---|
| ห้องแผนก | สมาชิกแผนก ผู้บริหาร ผู้ดูแลระบบ | เหมือนกัน |
| ห้องโครงการ | สมาชิกโครงการ (รวมผู้รับจ้าง) + สมาชิกแผนก/ผู้บริหาร | สมาชิกโครงการ |
| ภายใน กฟผ. | สมาชิกโครงการที่ไม่ใช่ผู้รับจ้าง + สมาชิกแผนก/ผู้บริหาร | สมาชิกโครงการที่ไม่ใช่ผู้รับจ้าง |
| ห้องของการประชุม | ผู้เข้าประชุม และผู้ที่เห็นการประชุมนั้น | ผู้เข้าประชุม |

- **ประชุม**: ประชุมโครงการ (เชิญผู้รับจ้างได้) · ประชุมภายใน กฟผ. (เชิญผู้รับจ้างไม่ได้) · ประชุมแผนก — ผู้นัดได้: เจ้าของ/ผู้ควบคุมงาน/กรรมการ/หัวหน้าของโครงการ หรือสมาชิกแผนก (ประชุมแผนก)
- แก้ไขนัด บันทึกการประชุม และงานที่มอบหมาย: ผู้นัด เจ้าของโครงการ ผู้มีสิทธิ์แก้ไขโครงการ — ผู้รับผิดชอบงานติ๊กงานของตนว่าเสร็จได้
- Google: เซิร์ฟเวอร์กรองข้อความตามสิทธิ์ (ผู้รับจ้างไม่ได้รับข้อความห้องภายในเลย) · SharePoint/OneDrive: กรองที่หน้าเว็บ — ผู้ที่เปิดไฟล์/รายการข้อมูลตรงอ่านได้ทุกห้อง จึงไม่ควรใช้ห้องภายในคุยเรื่องลับเมื่อผู้รับจ้างมีสิทธิ์ในไซต์/โฟลเดอร์

## 4.1 แบบฟอร์มและระเบียบ รายงานประจำวัน และอีเมลรายงาน (1.0.5)

**แบบฟอร์มมาตรฐานในระบบ** (เมนู "แบบฟอร์มและระเบียบ" และปุ่ม "พิมพ์" ในหน้าที่เกี่ยวข้อง)

| แบบ | ชื่อ | พิมพ์จาก | ข้อมูลที่กรอกให้ |
|---|---|---|---|
| PT-F01 | ใบขออนุมัติ / แจ้งเรื่อง | หน้าเรื่องขออนุมัติ · หน้าส่งเรื่อง (แบบเปล่า) | เลขที่เรื่อง หมวด รายละเอียด ไฟล์แนบ ผลการพิจารณาและความเห็นทุกขั้น ผลโหวต |
| PT-F02 | รายงานประจำวันของผู้ควบคุมงาน | รายงานประจำวัน | อากาศ คนงาน เครื่องจักร งาน วัสดุ การหยุดงาน ความปลอดภัย ข้อสั่งการ |
| PT-F03 | รายงานผลการปฏิบัติงานประจำสัปดาห์ | รายงานประจำวัน · คลังแบบฟอร์ม | ผลงาน/แผน สรุป 7 วัน ปัญหา เรื่องค้างพิจารณา |
| PT-F04 | บันทึกการประชุม | หน้าการประชุม | ผู้เข้าประชุม วาระ สรุป งานที่มอบหมาย |
| PT-F05 | บันทึกการตรวจรับงานจ้าง (งวดงาน) | รายงานประจำวัน · คลังแบบฟอร์ม | ข้อมูลสัญญา ผลงาน ช่องลงนามตามลำดับกรรมการ |
| PT-F06 | ใบสั่งการ / ข้อแนะนำ | รายงานประจำวัน | ข้อสั่งการของวันนั้น |

**คลังเอกสาร** — ผู้ดูแลระบบกด "เพิ่มเอกสาร": อัปโหลดไฟล์ (Word/Excel/PDF) หรือใส่ลิงก์ เลือกประเภท (แบบฟอร์ม · กฎหมาย/ระเบียบ · มาตรฐานงาน · คู่มือ · รายการตรวจสอบ) ประเภทงาน หมวดเรื่องขออนุมัติ และ "ใช้กับงาน"
(เรื่องขออนุมัติ · รายงานประจำวัน/สัปดาห์/เดือน · การประชุม · เอกสารที่ต้องส่ง · ส่งมอบ/ตรวจรับ) — ระบบแสดงในหน้านั้นของทุกโครงการโดยอัตโนมัติ
ตั้ง "เฉพาะเจ้าหน้าที่" เพื่อไม่ให้ผู้รับจ้างเห็น · ปิดใช้ฉบับเก่าโดยไม่ต้องลบ · ไซต์ SharePoint ต้องกด "อัปเดตโครงสร้างข้อมูลในไซต์" ก่อน

**รายงานประจำวัน** — แท็บในโครงการ: ผู้ที่บันทึกความคืบหน้าได้ (เจ้าของ/ผู้ควบคุมงาน) บันทึกวันละ 1 รายงาน แก้ไขภายหลังได้ (ผู้บันทึกเดิมยังคงอยู่) ·
สมาชิกโครงการที่ไม่ใช่ผู้รับจ้าง ผู้บริหาร และสมาชิกแผนกเปิดอ่านได้ · ติ๊ก "ส่งรายงานนี้ทางอีเมลทันที" เพื่อส่งให้ผู้รับระดับ "ทุกเรื่อง"

| อีเมล | เวลา (ค่าเริ่มต้น) | ผู้รับ |
|---|---|---|

| รายงานประจำสัปดาห์ | ศุกร์ 17:00 | คณะกรรมการตรวจรับ เจ้าของ ผู้ควบคุมงาน หัวหน้า (ไม่รวมผู้รับจ้าง) |

- **Google**: เซิร์ฟเวอร์ส่งเองตามเวลา (ตัวตั้งเวลา `hourlyJobs`) — ตรวจสถานะ/ติดตั้งได้ที่หน้าตั้งค่า ถ้าหน้าตั้งค่าแจ้งว่ายังไม่ได้ติดตั้ง ให้กด "ติดตั้งตัวตั้งเวลา" หรือรัน `installTriggers`

- ส่งด้วยมือ: เจ้าของโครงการ/ผู้ควบคุมงานส่งรายงานประจำวันและประจำสัปดาห์ของโครงการตนจากแท็บรายงานประจำวัน · ผู้ดูแลระบบ/ผู้บริหารส่งรายงานประจำเดือนจากหน้าสรุปผู้บริหาร

**สรุประดับความปลอดภัย**
- **Google Drive**: ทุกคำสั่งตรวจที่เซิร์ฟเวอร์ (Apps Script) ด้วยเซสชันจากรหัสทางอีเมล — แก้หน้าเว็บหรือส่งคำสั่งเองก็ข้ามสิทธิ์ไม่ได้ ผู้ใช้ไม่ได้รับสิทธิ์ในไฟล์ Google Sheet → **เหมาะที่สุดเมื่อมีผู้รับจ้างภายนอก**
- **SharePoint / OneDrive**: หน้าเว็บตรวจสิทธิ์ก่อนบันทึก และ Microsoft ตรวจสิทธิ์ของไซต์/โฟลเดอร์ — ผู้ที่มีสิทธิ์**แก้ไข**ไซต์/โฟลเดอร์สามารถเปิดข้อมูลแก้ตรงด้วย SharePoint/OneDrive ได้ จึงควรให้สิทธิ์แก้ไขเฉพาะคนในองค์กรที่ไว้ใจได้ และให้หัวหน้า/ผู้ติดตามเป็น "ดูอย่างเดียว" (OneDrive ทำให้อัตโนมัติด้วยปุ่ม "ให้สิทธิ์เข้าถึงโฟลเดอร์") · OneDrive/SharePoint เก็บประวัติเวอร์ชันให้ตรวจย้อนหลังและกู้คืนได้

**ข้อควรปฏิบัติ**
1. กำหนด **ผู้ที่สร้างโครงการได้** (เช่น `@egat.co.th`) และ **ผู้ดูแลระบบ** ให้ชัดเจนตั้งแต่วันแรก
2. ลิงก์เชิญของ Google มี Access key — ส่งเฉพาะคนในทีม ถ้าหลุดให้รัน `resetAccessKey` แล้วส่งลิงก์ใหม่ · ให้ทุกคนออกจากระบบ: `logoutEveryone`
3. ถอดสมาชิกที่พ้นหน้าที่ออกจากโครงการทันที (มีผลทันที — ผู้ที่ถูกถอดจะไม่เห็นโครงการนั้นอีก) และ OneDrive: ถอนสิทธิ์โฟลเดอร์ด้วย
4. ออกจากระบบทุกครั้งบนเครื่องสาธารณะ · อย่าแก้คอลัมน์ `Data` หรือไฟล์ใน `_data` ด้วยมือ
5. ผู้รับจ้างภายนอกเห็นข้อมูลทั้งหมด**ของโครงการตน** (BOQ ความคืบหน้า เอกสาร) — ถ้ามีข้อมูลภายในที่ไม่ควรเปิดเผย ให้เก็บนอกระบบ หรือใช้โครงการแยก

## 6. ผลการตรวจทานความปลอดภัย (1.0.2)

ตรวจทุกคำสั่งที่เขียนข้อมูลทั้งฝั่งเซิร์ฟเวอร์ (Code.gs 22 คำสั่ง) และฝั่งหน้าเว็บ (store.js) พร้อมชุดทดสอบอัตโนมัติที่ลองทำรายการข้ามสิทธิ์ในทุกบทบาท

| สิ่งที่พบ | การแก้ไข |
|---|---|
| Google: ผู้มีสิทธิ์แก้โครงการ ตั้งโฟลเดอร์ Drive ของโครงการให้ชี้ไปโฟลเดอร์ของโครงการอื่นได้ แล้ว "ดึงไฟล์จาก Drive" เพื่อเห็นรายชื่อ/ลิงก์ไฟล์ข้ามโครงการ | เปลี่ยนโฟลเดอร์ได้เฉพาะผู้ดูแลระบบ (เซิร์ฟเวอร์บังคับ) |
| Google: บันทึก BOQ ด้วยรหัสรายการของโครงการอื่นได้ (ข้อมูลปนกัน) | รหัสที่เป็นของโครงการอื่นถูกสร้างใหม่ |
| Google: แนบไฟล์โดยอ้างรหัสเรื่องของโครงการอื่นได้ | ตรวจว่าเรื่องอยู่ในโครงการเดียวกัน |
| Google: ส่งค่า "ผู้สร้าง/วันที่สร้าง" ของโครงการเองได้ | ใช้ค่าเดิมจากเซิร์ฟเวอร์เสมอ |
| เจ้าของโครงการกด "ผ่าน" แทนกรรมการได้ทุกขั้น | ขั้นของกรรมการแต่ละลำดับ เฉพาะกรรมการลำดับนั้น (เจ้าของแทนได้เมื่อไม่มีผู้ใดในลำดับนั้นเท่านั้น) |
| SharePoint: ถ้ายังไม่กำหนดผู้ดูแลระบบ ทุกคนในไซต์เป็นผู้ดูแล | ผู้ตั้งค่าไซต์ถูกบันทึกเป็นผู้ดูแลระบบทันที (ไซต์เดิมแสดงคำเตือนให้กำหนด) |
| ลิงก์เอกสารที่ไม่ใช่ http(s) (เช่น `javascript:`) อาจถูกเปิดได้ถ้ามีคนแก้ข้อมูลตรง | รับและเปิดเฉพาะ http(s) |
| สลับ SharePoint/OneDrive แล้ว token ของ Microsoft ถูกลบ | เก็บ token แยกตามแอป |

สิ่งที่ตรวจแล้วไม่พบปัญหา: การเข้าสู่ระบบ Google (รหัสใช้ครั้งเดียว จำกัดจำนวนครั้ง เซสชันเก็บเป็น hash) · การกรองโครงการที่ส่งให้ผู้ใช้ · การแต่งตั้งสมาชิกโดยผู้ที่ไม่ใช่เจ้าของ · การเปลี่ยนเจ้าของผ่านการบันทึกโครงการ · ค่ากลาง/นำเข้าข้อมูลโดยผู้ที่ไม่ใช่ผู้ดูแล · ข้อความผู้ใช้ทุกจุดผ่านการ escape (กัน XSS) · อีเมลแสดงใน iframe แบบ sandbox
